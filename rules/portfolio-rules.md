## 2. 반응형 브레이크포인트

브레이크포인트 3단계를 정확히 따른다. 임의로 추가·변경 금지.

| 범위 | 레이블 | 비고 |
|------|--------|------|
| `1281px` 이상 (최대 3840px) | **Desktop** | 기본 레이아웃 기준 |
| `769px` – `1280px` | **Tablet** | `@media (max-width: 1280px)` |
| `320px` – `768px` | **Mobile** | `@media (max-width: 768px)` |

- 텍스트 사이즈는 `clamp()` 또는 미디어 쿼리로 각 구간마다 별도 지정
- 이미지 사이즈는 추후 정확한 수치 반영 예정 — 현재는 `width: 100%` + `aspect-ratio` 유지
- 반응형이 깨지더라도 **지시 없이 레이아웃 구조 변경 금지** — 먼저 보고하고 지시를 받을 것

## 3. 금지 규칙 (절대 위반 금지)

### 3-1. 콘텐츠 관련
- [ ] 임의로 불필요한 섹션 추가하지 말 것
- [ ] 텍스트(카피) 임의로 변경하지 말 것
- [ ] **영어 카피를 한국어로 바꾸지 말 것** (반대도 금지)
- [ ] 프로젝트 설명을 요약하거나 내용을 추가하지 말 것
- [ ] 빈 placeholder 텍스트 (`Lorem ipsum` 등) 임의 삽입 금지

### 3-2. UI / 스타일 관련
- [ ] 요청한 것 이상의 과도한 애니메이션 추가 금지
- [ ] 버튼 스타일 임의 변경 금지
- [ ] **명시적 요청이 없는 한 색상 하드코딩 금지** — 반드시 CSS Variable(`var(--...)`) 사용
- [ ] **기존 class명 삭제·변경 금지** (JS 동작에 연결된 것: `.reveal`, `.active`, `.work-card`, `.filter-tab` 등)
- [ ] 요청 안 한 모달·팝업·툴팁 추가 금지
- [ ] 폰트 패밀리(Manrope) 임의 변경 금지

### 3-3. 구조 관련
- [ ] 지시 없이 페이지 구조(섹션 순서, HTML 계층) 바꾸지 말 것
- [ ] 파일 경로·URL 구조 임의 변경 금지 (상대경로 `../work/` 등)
- [ ] `section[id]` 패턴 유지 — script.js active nav 감지에 필요
- [ ] 빌드 도구·외부 라이브러리·npm 패키지 추가 금지

### 3-4. 작업 방식
- [ ] **한 번에 하나의 파일만 수정** — 여러 파일 동시 수정 금지
- [ ] **수정 전 반드시 해당 파일 전체를 Read한 뒤 작업**
- [ ] 요청 범위를 벗어난 파일 건드리지 말 것
- [ ] **git push는 명시적으로 요청받은 경우에만 실행**

## 4. 권장 작업 방식

| 상황 | 처리 방법 |
|------|-----------|
| 규칙과 충돌하는 요청 | 작업 전 멈추고 → 충돌 이유를 명확히 설명 → 해결책을 차근차근 제시 → 확인받고 진행 |
| 오류 발생 시 | 수정 전 원인과 영향 범위를 먼저 설명, 그 후 작업 |
| 반응형이 깨지는 경우 | 레이아웃 임의 변경 금지 — 어디서 어떻게 깨지는지 설명과 함께 보고 |
| 내용이 모호한 지시 | 작업 전 구체적으로 재확인 요청 |
| 기존 코드와 충돌 발생 | 선택지 제시 후 결정을 기다림 |

## 6. 디자인 원칙 (참고용)

이 포트폴리오는 미국 채용 시장을 타겟으로 한다. 작업 시 아래 원칙을 염두에 둘 것.

- **명확성 우선**: 화려함보다 읽기 쉽고 탐색하기 쉬운 구조
- **케이스스터디 중심**: 결과(impact)와 프로세스(why)가 잘 드러나야 함
- **일관성**: GNB·Footer·카드·버튼 등 공통 컴포넌트는 모든 페이지에서 동일하게 유지
- **접근성**: `aria-label`, 시맨틱 태그, 충분한 color contrast 유지
- **퍼포먼스**: 불필요한 JS·외부 리소스 추가 금지
